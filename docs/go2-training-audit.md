# Go2 训练审计: 地形覆盖 与 "躯干高度/倾角/速度" 波动

> 两个问题:
> 1. 训练是不是全在平地上?
> 2. 要不要把躯干高度 / 倾角 / 速度估计误差加进奖励惩罚项? (看曲线波动有点大)
>
> 全部结论都有实测数字支撑, 复现命令见 §6。审计脚本: `sim/analyze_go2_walk.py`

---

## 0. 结论先行

| 问题 | 结论 |
|---|---|
| 训练地形 | **不是平地**. 交付模型 (v2 硬接触, 37.26M 步) 全程在**粗糙地形高度场**上训练: 12m×12m, 起伏 5cm + 6 块 6cm 台地 + 2 条 5 级楼梯 (最高 0.30m), 随机出生 ±5m。平地在训练里只是"地形的一个子集" (50.5% 的格子 <1cm, 原点强制压平)。**但只有一张地图** (seed 0 固定), 这是真正的弱点。 |
| 高度惩罚 | **已经有, 而且是最重的成本项之一**: base_height = -200·(z−0.268)² (v2 经 `--climb_reward` 打开), 另有 vertical_vel = -2·vz²。平地实测每步 −0.145 / −0.136 (合计 −0.28), 是除力矩外最大的两项成本 —— 相对可复算的 2.6/步速度跟踪正奖励约 11%, 若把足端/相位类正奖励也算进去约 5%。**不需要再加**, 加了只会更僵、力矩更高。 |
| 倾角惩罚 | 有但**几乎为零**: orientation = -1·(gx²+gy²), 3° 倾角只扣 −0.0037/步 (≈0.1%)。这是**故意的**——倾角起伏在步频上, 压它就是压步态。真要压, 应改成"压横滚**偏置**"而不是压振荡。 |
| 速度估计误差 | **不是奖励项能解决的问题**。真机上没有真值, 惩罚算不出来。正确做法是把估计误差注入**观测** (bias/drift/latency), 让策略不迷信速度; 以及修里程计本身。 |
| 真正该修的 | 数据里暴露了三个**步态缺陷**: ①对角支撑相不平衡 **0.54 vs 0.31** (1.74×); ②指令 wz=0 时系统性偏航 **−4.1°/s**; ③髋/大腿力矩在平地 0.5m/s 就有 **3–5% 帧顶到 23.7 N·m 上限**。这三条比 z/tilt 的 RMS 重要得多。 |

## 1. 问题一: 训练地形覆盖

`sim/start_go2_train.sh` (实际跑出交付模型的那条命令) 带的地形相关开关:

```bash
--terrain --height_scan --push --obs_noise --climb_reward --soft_landing ...
```

### 1.1 地形是什么

`models/go2/assets/terrain.png` (128×128 uint16) + `terrain.json`:

| 项 | 值 |
|---|---|
| 世界尺寸 / 网格 | 12 m × 12 m, 128×128 (**格距 9.4 cm**) |
| 高度量程 | 0 … 0.30 m (elevation_z) |
| 内容 | 平滑随机起伏 (amp 5 cm, σ=2 格) + 6 块矩形台地 (各 6 cm) + 2 条 5 级楼梯 (每阶 6 cm) |
| 原点 | 强制 h(0,0)=0 并平滑过渡 (保证 reset 与平地档一致) |
| 高度分布 | 50.5% 格子 <1 cm; 中位 0.98 cm; 75% 分位 4.9 cm; 95% 分位 20.6 cm; max 30 cm |

所以"平地"在训练里占一半面积, 但它不是"平地档训练"——策略从 4096 个随机出生点出发,
走过的多数是"缓起伏 + 台地 + 楼梯"的混合地面。

### 1.2 随机化到什么程度

| 维度 | 训练里的随机化 | 备注 |
|---|---|---|
| 出生点 | xy ~ U(−5,5) m, yaw 随机, z = 地面 + 0.32, 初速 ±0.3 | `--terrain` 隐式打开 |
| 地形 | **无** (固定 seed 0 的同一张图) | 环境里 hfield 是闭包常量, 所有 env 共享 |
| 高度扫描 | 35 点, 地面高度加 U(−0.02, 0.02) m 噪声 | `height_scan.noise=0.02` |
| 观测噪声 | lin/ang vel ±0.05, gravity ±0.02, dof_pos ±0.01, dof_vel ±0.15 | 白噪声, 均匀分布 |
| 外力推挤 | 每 250 步 (5s) 水平速度冲量 ±0.5 m/s | `--push` |
| 摩擦 | 固定 (足 0.4, 地面 1.0), 不随机 | 没做 domain rand |

**这条是问题一的真正答案**: 训练不是"只平地", 但比"地形训练"听起来弱——**只有一张地图**,
策略可以把这张图的形状记下来。真机上换一块地形, 泛化只能靠 35 维高度扫描的局部几何。
要补, 应当做多地图 (或每段训练换一张图), 而不是回到平地。

## 2. 问题二: 波动到底有多大、是不是"缺惩罚"

### 2.1 实测波动 (交付策略, 平地, cmd vx=0.5, 稳态 3–7 s)

数据源: `mjx-go2-mujoco2ros2/logs/go2_view/frames.csv` (15 s 记录; 15 Hz 抽帧)

| 量 | mean | std | p5 | p95 | 判读 |
|---|---|---|---|---|---|
| 躯干 z | 0.2916 m | **0.0130** | 0.2709 | 0.3123 | 站高比训练目标高 2.4 cm; 起伏 ±1.3 cm |
| 倾角 (roll/pitch 合成) | 2.97° | **1.82°** | 0.73° | 6.62° | max 8.3°; 其中 roll 常值偏置 −2.25° |
| 机体 vx | 0.524 m/s | 0.059 | 0.424 | 0.606 | 比指令**快 5%** |
| 机体 vy | +0.005 m/s | 0.044 | — | — | 跟踪正常 (世界系 vy=0.042 是偏航造成的) |
| vz | −0.007 m/s | 0.261 | −0.448 | 0.313 | 垂直速度起伏 |

### 2.2 频率: 波动就是步态本身

FFT (15 Hz 采样):

| 量 | 主峰 |
|---|---|
| 躯干 z | **3.73 Hz** (幅度 1.00), 1.74 Hz (0.89) |
| 倾角 | **1.99 Hz** (1.00), 3.48 Hz (0.61) |

配置的步频 `gait_freq=1.8 Hz`. z 的主峰 3.7 Hz ≈ **2× 步频** = 每落地一次弹一下;
倾角主峰 2.0 Hz ≈ **1× 步频** = 支撑多边形左右切换。这是 trot 的标准特征, **不是控制器不稳定**。
压这种成分 = 压步态: 腿会更僵、力矩更大、落地冲击更硬, 真机上通常是负收益。

### 2.3 现有奖励项每一步实际扣了多少 (平地, 按 env 公式复算)

| 奖励项 | 公式 | 每步 mean | 说明 |
|---|---|---|---|
| linear_vel_tracking (+) | 2·exp(−‖v−cmd‖²/0.25²) | **+1.813** (满 2.0) | 差 0.19 来自 5% 超速 + 速度起伏 |
| angular_vel_tracking (+) | 1·exp(−(wz−cmd)²/0.25²) | **+0.802** (满 1.0) | **差 0.20 几乎全来自 −4.1°/s 偏航** |
| base_height (−) | −200·(z_rel−0.268)² | **−0.145** | 见下方拆解 |
| vertical_vel (−) | −2·vz² | **−0.136** | 纯振荡 |
| orientation (−) | −1·(gx²+gy²) | **−0.0037** | 3° 倾角几乎免费 |
| xy_angular_vel (−) | −0.05·(ωx²+ωy²) | −0.0115 | 很小 |
| torque (−) | −2e-4·Στ² | **−0.174** | 四个髋关节均值 4.6–10.7 N·m |
| 合计 (可复算部分) | | **+2.146** | 尚未计足端/相位/对称等项 |

**高度成本拆解**: 稳态站高比目标高 **+0.024 m** → 常量偏移项 **−0.111**, 振荡项只有 **−0.034**。
也就是说这个 −0.145 里 **77% 是在为"站得偏高"付常数罚金, 不是为"抖动"付费**。
→ 想在高度上做文章, 该修的是平地站高 offset (为什么比训练目标高 2.4 cm), 而不是给振荡加权重。

### 2.4 三个判断

**(a) 高度: 不要加。** 已有 −200×(平方误差), 而且是全奖励面里最大的成本项之一; 振荡本身只占其中 23%。
再加 = 更低更僵的姿态 + 更高膝力矩 (现在髋/大腿已经 3–5% 帧饱和)。

**(b) 倾角: 现在确实几乎不罚 (−0.0037), 但不要直接加权。** 倾角 1.82° std / 6.6° p95 在 trot 正常范围内;
按 sin²θ 加权重, 要加到能影响行为需要 −10…−50, 那等于直接对抗步态。
如果目标只是消掉 **roll 的 −2.25° 常值偏置**, 正确做法是加一个**低通偏置惩罚**
 ( `-W·EMA(roll)²`, W≈50, 只罚慢变成分), 而不是罚瞬时倾角。

**(c) 速度估计误差: 不属于奖励项。** 真机上没有真值, "估计误差"这个量算不出来。
现在训练里 obs 0:3 是**真值 + 白噪声 ±0.05 m/s** (`obs_noise.lin_vel=0.05 × obs_scale 2.0`),
而腿式里程计的真实误差是**有偏、慢漂**的 (本项目 LegOdometry 在 0.5 m/s 时会发散到 −0.18)。
正确做法是**把误差注入观测**: 每回合常数偏置 ±0.15 m/s + OU 慢漂 + 20–40 ms 延迟。这是 sim2real 的正解。

## 3. 数据里暴露的真正缺陷 (比 RMS 重要)

### 3.1 对角支撑相不平衡 1.74×

同一段记录, 四足触地占空比:

```
FR 0.52   FL 0.31   RR 0.31   RL 0.56     对角对 A(FR+RL) = 0.54
                                           对角对 B(FL+RR) = 0.31
```

训练物理的 CPU 评测也复现: duty = [0.528, 0.368, 0.344, 0.518] → A/B = **1.47×**。
trot 的 A/B 应该 ≈ 1.0。**A 对承重多 74%**, 后果: 左右载荷不均 (真机上 A 侧电机更热)、
横滚偏置 −2.25°、以及偏航漂移 (偏航由不对称的蹬地力矩产生)。

### 3.2 指令 wz=0 却系统性偏航 −4.1°/s

`yaw +4.64° → −12.88°` (10 s), 线性漂移 −4.10 °/s = −0.082 rad/s。
按 0.5 m/s 走 6 m (12 s) 会偏 49°: 直线走成圆弧, 横向偏 ≈ 2.3 m —— 已经不能靠"方向舵"补救, 导航层必须一直纠偏。

补充: 这个漂移**方向会随初始条件翻转** (部署场景评测里量到 +4.6°/s), 训练 XML 评测 16 seed 均值只有 −0.3°/s。
即它是**对称性破缺的双稳态** (gait 有两个镜像吸引子, 初始瞬态决定落哪个), 不是固定 bias。
真机上每次上电都可能选不同方向 → 必须修, 否则导航层得一直纠偏。

### 3.3 力矩饱和与超速

| 检查 | 值 |
|---|---|
| 髋/大腿力矩顶 23.7 N·m 上限的帧占比 | FR_hip 3.3%, FL_hip 4.9%, RR_thigh 3.3% (p99 = 23.7) |
| 膝关节峰值 | 32.5 N·m / 45.43 上限 (平地), 地形评测峰值 45.4 (顶限) |
| 实际速度 | 0.524 vs 指令 0.500 → **+5%** |

平地 0.5 m/s 就把髋顶到限位, 说明步态偏"撑"; 真机连续跑会热。超速 5% 是训练里 sigma 太宽 (0.25) 的直接后果。

## 4. v3 建议 (按性价比排序)

**不动 height/tilt/vertical_vel 的现有权重。** 改这四项:

| # | 改动 | 具体数值 | 目的 | 风险 |
|---|---|---|---|---|
| 1 | 观测速度注入**真实估计误差** | 每回合常数 bias U(±0.15) m/s (逐轴) + OU 慢漂 σ=0.1, τ=2 s + 20–40 ms 延迟 | 直接回答"速度估计误差"; 让策略不迷信里程计 | 跟踪精度可能略降; 需要重训验证 |
| 2 | 对称项**按直线指令门控**并加权 | `symmetry_w −0.4 → −1.2`, 再乘 `exp(-(wz_cmd/0.3)²)` | 修 A/B 占空比 1.74× (→ 偏航漂移/横滚偏置/单侧过热) | 权重过大可能拖慢转弯 (wz 指令 ±1.5); 需扫 −0.8/−1.2/−2.0 |
| 3 | 角速度跟踪**收紧 sigma** | `tracking_velocity_sigma` 0.25 → 0.12 (角速度项单独用 sigma_wz) | 让 0.08 rad/s 的偏航从"扣 20%"变成"扣 60%", 逼它走直 | 指令阶跃时可能更抖; 建议先只调角速度项 |
| 4 | 地形**多地图** | 再生成 2–3 张 (不同 seed/幅度), 每段训练换一张, 最后在**留出地图**上评测 | 补问题一的最大弱点: 现在只有一张图 | 需要改训练脚本传图 / 分阶段续训; 工作量最大 |

可选 (不推荐先做): `-W·EMA(roll)²` (W≈50) 消 roll 常值偏置;
`orientation` 权重保持 −1.0 不动。

预计收益 (可测): 偏航漂移 −4°/s → <1°/s; duty A/B 1.5 → <1.15; 髋饱和帧占比 3–5% → <1%;
平地 15 s 横滚偏置 −2.2° → <1°。

## 8. v4 结果 (2026-10-18, 混合地形)

* v4 = v2 配方 + 混合地形 (n=128), 40.55M 步, best eval_reward 1152.5; 异常 0。
* 平地 (训练 XML): 100% 存活, vx 0.516, trot 判定 **100%** (v2: 0%), 对角占空比 1.38x
  (v2 1.68x), 滑移 0.337 (v2 0.392)。
* 部署闭环 (平地 15s): 偏航漂移 oracle **-0.35** vs v2 3.22 deg/s; estimator **0.93** vs 1.52;
  v4 超速 +18% (oracle), 倾角 RMS 6.2 vs 3.0°。
* 地形 (warp 训练物理, 随机出生 128 env x 6s): v4 **74.2%** vs v2 **74.2%** —— 完全一致,
  混合地形训练没有带来地形鲁棒性提升 (混合图本身比旧地形更缓)。
* CPU MuJoCo 地形评测仍不可用 (同一策略 warp 0.48 m/s vs CPU 0.13-0.19); 已排除求解器
  迭代数 (20/10 与 100/50 都远达不到 warp) -> 差异在 hfield 接触实现 (R1)。
* 部署框架默认策略已切到 v4 (profile go2), 回滚档 go2_v2。
* 详见 docs/go2-v4-terrain-report.md。
